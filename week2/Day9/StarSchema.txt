1. FACT TABLE (Main Table)
Definition

Fact table stores:

Transactions
Numeric values (measures)

Example: fact_orders
order_id	product_id	customer_id	date_id	amount	quantity
101	P1	C1	D1	50000	1
102	P2	C2	D2	15000	2
103	P1	C3	D3	50000	1

Key Points:
Contains IDs (foreign keys)
Contains numeric values
Large table (millions of rows)

“Fact table tells WHAT happened”

2. DIMENSION TABLES (Supporting Tables)
Definition

Dimension tables store:

Descriptive information
Attributes

DIMENSION 1: Product Table
dim_product
product_id	product_name	category
P1	Laptop	Electronics
P2	Mobile	Electronics

DIMENSION 2: Customer Table
dim_customer
customer_id	customer_name	city
C1	Ravi	Hyderabad
C2	Sita	Chennai

DIMENSION 3: Date Table
dim_date
date_id	full_date	month	year
D1	2024-01-01	Jan	2024
D2	2024-01-02	Jan	2024

Key Points:

Contains descriptive columns
Smaller in size
Used for filtering/grouping

“Dimension tables tell DETAILS about the data”

3. HOW THEY CONNECT
Relationship
          dim_product
               |
dim_customer — fact_orders — dim_date

Fact table connects to all dimensions using IDs

4. HOW REPORTING WORKS
Business Question:

“Total sales by product and city”


SELECT p.product_name, c.city, SUM(f.amount)
FROM fact_orders f
JOIN dim_product p ON f.product_id = p.product_id
JOIN dim_customer c ON f.customer_id = c.customer_id
GROUP BY p.product_name, c.city

Explanation:
Fact → gives amount
Dimensions → give names/details

5. WHY NOT STORE EVERYTHING IN ONE TABLE?

Problem with single table:
order_id	product_name	category	customer_name	city	amount

Issues:

Data duplication
Large size
Hard to maintain

Star Schema Advantage:

No duplication
Easy to query
Faster performance
